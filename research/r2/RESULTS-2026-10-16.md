# R2 first result: what the verification gate catches on real production runs (2026-10-16)

Aggregates only; no production data is stored in the repo. Gate = deployed image `backend:6651a1a` (identical to this
branch's `backend/app`). Seed `r2-2026-10-16`. Design: `docs/research/R2_PLANTED_ERROR_EVAL.md` (see its §10 change log).

## Data
- Read-only export of all 287 committee runs before 2026-10-16: **199 clean**, 74 without claims, **14 already fail the
  unmodified gate** (excluded; the manifest's `excluded_run_count` = 0 because they were dropped at export, not at load).
- Every clean run already carries warnings (1,189 `warn` results across the 199 runs before anything is planted), so
  detection is measured **relative to each run's untouched baseline**: an instance is "detected" only if it has a non-pass
  result its source run did not have. (Without that, every type, controls included, reads 100%.)
- 1,000-instance design, minus E8a/E8b/E8c (narrative errors): production narrative generation is off, every narrative
  row is `skipped`, so those types cannot be planted. 850 instances from 100+ runs, 15 symbols; C0 = one per run (100 runs).
- `run_time` = each run's `created_at` (production stores none; same as the publish path), which can make point-in-time
  checks slightly lenient: errors of that kind may be under-counted, never over-counted.

## Result (gate only, $0; LLM-reviewer arm not run)

| | N | Caught | Rate | 95% upper bound on miss / false alarm |
|---|---:|---:|---:|---:|
| Catchable types (E1a-d, E3, E4, E5, E6, E7a, E9, E10) | 550 | 531 | 96.5% | |
| ... excluding the 19 uninformative E5 instances (below) | 531 | 531 | **100%** | ≤ 6% per type; E5 ≤ ~10% (31 informative) |
| Blind spots by design (E2 wrong field, E7b payload+hash rewrite) | 100 | 0 | 0% | (expected: the gate can't see these) |
| Controls C0 (untouched) / C1 (benign edit) | 100 / 100 | 0 / 0 | **0% false alarms** | ≤ 3% each |

**E5 (stale data, expected `warn`):** 31 of 50 detected. All 19 "misses" were planted on claims the untouched run already
flagged as stale, so the planted error could not add a new flag: uninformative, not gate misses. Follow-up: the injector
should pick E5 targets that are not already stale.

## What this does and doesn't show
- On real runs, every catchable planted error that could produce a new flag did, with no false alarms on 200 controls.
- The two designed blind spots are confirmed blind: an error in a field the gate doesn't compare, and a payload rewritten
  together with its hash, both pass.
- Not shown: narrative errors (E8, untestable while narratives are off), the LLM-reviewer comparison (~$2, needs owner
  approval), and anything about errors outside the 16 planted types. The gate runs in shadow mode in production.

Reproduce: `bash D:/tools/r2-export/export.sh` (read-only), then
`UNTESTABLE=E8a,E8b,E8c bash D:/tools/r2-export/build.sh <export dir>`.
